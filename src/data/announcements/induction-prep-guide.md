## Step 1: Basics

These aren't compulsory, so don't worry if you're already familiar with some of them or haven't covered everything.

### Linux

Get comfortable with the terminal (`ls`, `cd`, `grep`, `find`, `chmod`, etc.). Understand files, directories, permissions, and processes.

- [Linux Journey](https://linuxjourney.com/)
- [OverTheWire: Bandit](https://overthewire.org/wargames/bandit/)

### Programming

Pick one language. You don't need to learn all three. Python is a good starting point.

| Language | Why | Resource |
|----------|-----|----------|
| Python | Scripting and automation | [learnpython.org](https://www.learnpython.org/) |
| C | Memory, pointers, and low-level concepts | [learn-c.org](https://www.learn-c.org/) |
| C++ | Problem-solving and programming fundamentals | [learncpp.com](https://www.learncpp.com/) |

### Networking

Learn about IP addresses, ports, TCP/UDP, DNS, HTTP/HTTPS, and what happens when you open a website.

- [Practical Networking](https://www.practicalnetworking.net/)
- [Cloudflare Learning Center](https://www.cloudflare.com/learning/)

## Step 2: Explore the domains

Cybersecurity covers a lot of different areas. Rather than trying to learn everything, spend some time exploring a few domains and see what interests you.

| Domain | What it's about | Start here |
|--------|-----------------|------------|
| **Web Exploitation** | Finding vulnerabilities in websites, such as SQL injection, XSS, and broken authentication | [PortSwigger Web Security Academy](https://portswigger.net/web-security) |
| **Reverse Engineering** | Understanding what a program does without having its source code | [crackmes.one](https://crackmes.one/), [Ghidra](https://ghidra-sre.org/) |
| **Pwn / Binary Exploitation** | Buffer overflows, stack memory, and binary vulnerabilities | [pwn.college](https://pwn.college/), [exploit.education](https://exploit.education/) |
| **Cryptography** | Encoding, encryption, hashing, XOR, and RSA basics | [CryptoHack](https://cryptohack.org/), [Cryptopals](https://cryptopals.com/) |
| **Digital Forensics** | Examining metadata, steganography, network captures, and files | [Wireshark Docs](https://www.wireshark.org/docs/), [dCode](https://www.dcode.fr/) |
| **OSINT** | Gathering information using publicly available sources | [OSINT Framework](https://osintframework.com/) |
| **Pentesting** | Testing systems for vulnerabilities through scanning, enumeration, and exploitation | [TryHackMe](https://tryhackme.com/) (the beginner paths are great), [HTB Academy](https://academy.hackthebox.com/) |
| **Adversarial AI** | Understanding attacks against AI models, including prompt injection and jailbreaks | [ARENA](https://arena-chapter0-fundamentals.streamlit.app/), [Adversarial Robustness](https://adversarial-ml-tutorial.org/), [Gandalf](https://gandalf.lakera.ai/), [PortSwigger LLM Attacks](https://portswigger.net/web-security/llm-attacks) |

### Extra: Reverse Engineering

If you want a more structured introduction to reverse engineering, **OpenSecurityTraining2 (OST2)** has free courses covering assembly and debugging.

- [Arch1001: x86-64 Assembly](https://ost2.fyi/Arch1001)
- [Dbg1012: Intro to GDB](https://ost2.fyi/Dbg1012)
- [OST2 home](https://ost2.fyi/)

These courses go into more detail than the other resources listed here, so you can start with the first few lessons and continue at your own pace.

## Step 3: Try a few CTFs

CTF (Capture The Flag) challenges are cybersecurity puzzles where you solve problems to find hidden flags. They're a good way to apply what you've learned.

Some places to get started:

- [picoCTF](https://picoctf.org/)
- [TryHackMe](https://tryhackme.com/)
- [OverTheWire](https://overthewire.org/)
- [pwn.college](https://pwn.college/)
- [CryptoHack](https://cryptohack.org/)
- [CTFlearn](https://ctflearn.com/)

If you get stuck, try reading a writeup after making a genuine attempt. Then, try solving a similar challenge on your own.

---

## A few things to remember

- Don't try to learn every domain. Pick one or two, spend a couple of days exploring each, and move on if something else interests you more.
- There are no prerequisites. You don't need prior cybersecurity or programming experience to attend the inductions.
- Don't just watch tutorials. Try things out, set up tools, and experiment in legal and controlled environments.
- Ask questions in the group. Basic questions are welcome, and everyone starts somewhere.
- Explore beyond this list. These are just starting points, and there's plenty more to learn.

The induction tasks may include questions similar to the beginner-level topics covered above.

This guide is intended to help you prepare, but we're not expecting you to master everything. We're more interested in your curiosity and willingness to learn.

Don't treat this as homework or a checklist. Explore the topics, try things out, and see what you enjoy.

## Optional: Write about what you learn

Writing about a topic is a good way to consolidate what you've learned and keep track of your progress.

If you'd like, write a short report about something you explored. It could be a CTF, a tool, or a particular topic. A Google Doc, Notion page, blog post, or GitHub README would all work.

Include:

- What you tried
- What you learned
- Where you got stuck and how you solved it
- Screenshots or commands, if relevant

A few things to keep in mind:

- Writing a report is completely optional. Not submitting one won't affect your induction.
- Write in your own words. AI is a useful tool, but it's a tool nonetheless. Writing this yourself will help you internalise all the knowledge you learned better than any AI summary.
- A *genuinely good* report may be considered during the interview, so it could be a useful addition.

Feel free to share your report in the group if you'd like feedback.
