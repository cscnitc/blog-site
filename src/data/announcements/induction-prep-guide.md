## 🧱 Step 1: Basics (optional but helpful)

> Not compulsory. Don't panic if you only know some of it. 😌

### 🐧 Linux

Get comfy with the terminal (`ls`, `cd`, `grep`, `find`, `chmod`...). Understand files, directories, permissions and processes.

- [Linux Journey](https://linuxjourney.com/)
- [OverTheWire: Bandit](https://overthewire.org/wargames/bandit/)

### 💻 Programming

Pick **ONE**. You don't need to learn all three. Python is the easiest start.

| Language | Why | Resource |
|----------|-----|----------|
| Python | Scripting and automation | [learnpython.org](https://www.learnpython.org/) |
| C | Memory, pointers, low-level concepts | [learn-c.org](https://www.learn-c.org/) |
| C++ | Problem-solving and fundamentals | [learncpp.com](https://www.learncpp.com/) |

### 🌐 Networking

IPs, ports, TCP/UDP, DNS, HTTP/HTTPS, and the classic question: *"what happens when you open a website?"*

- [Practical Networking](https://www.practicalnetworking.net/)
- [Cloudflare Learning Center](https://www.cloudflare.com/learning/)

## 🧭 Step 2: Peek into the domains

Cybersecurity is huge. Don't try to learn everything. **Sample a few** and see what clicks 👀

| Domain | What it's about | Start here |
|--------|-----------------|------------|
| 🌐 **Web Exploitation** | How websites break (SQLi, XSS, broken auth) | [PortSwigger Web Security Academy](https://portswigger.net/web-security) |
| 🔍 **Reverse Engineering** | Figuring out what a program does without the source code | [crackmes.one](https://crackmes.one/), [Ghidra](https://ghidra-sre.org/) |
| 💥 **Pwn / Binary Exploitation** | Buffer overflows, stack and memory stuff | [pwn.college](https://pwn.college/), [exploit.education](https://exploit.education/) |
| 🔐 **Cryptography** | Encoding vs encryption vs hashing, XOR, RSA basics | [CryptoHack](https://cryptohack.org/) |
| 🕵️ **Digital Forensics** | Metadata, stego, Wireshark, digging through files | [Wireshark Docs](https://www.wireshark.org/docs/), [dCode](https://www.dcode.fr/) |
| 🧩 **OSINT** | Finding stuff using only public info | [OSINT Framework](https://osintframework.com/) |
| 🎯 **Pentesting** | Legally hacking systems to find weaknesses before the bad guys do (scanning, enumeration, Burp Suite, Nmap) | [TryHackMe](https://tryhackme.com/) (the beginner paths are great), [HTB Academy](https://academy.hackthebox.com/) |
| 🤖 **Adversarial AI** | Tricking and breaking AI models (prompt injection, jailbreaks, LLM attacks). Very new and very fun! | [Gandalf](https://gandalf.lakera.ai/) (it's a game 😭), [PortSwigger LLM attacks](https://portswigger.net/web-security/llm-attacks), [OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/) |

### 🔍 Extra for Reverse Engineering

Want a proper structured course? **OpenSecurityTraining2 (OST2)** is free.

- [Arch1001: x86-64 Assembly](https://ost2.fyi/Arch1001)
- [Dbg1012: Intro to GDB](https://ost2.fyi/Dbg1012)
- [OST2 home](https://ost2.fyi/)

> It's a bit heavy, so even the first few lessons will put you ahead. 🔥

## 🚩 Step 3: Try a few CTFs

CTF (Capture The Flag) = hacking puzzles with flags to find. It's the best way to learn by doing.

- [picoCTF](https://picoctf.org/)
- [TryHackMe](https://tryhackme.com/)
- [OverTheWire](https://overthewire.org/)
- [pwn.college](https://pwn.college/)
- [CryptoHack](https://cryptohack.org/)
- [CTFlearn](https://ctflearn.com/)

Stuck? Read the writeup **after** genuinely trying, then try a similar challenge on your own 💪

## 📌 Few things to remember

- ❌ **Don't try to learn every domain.** Pick 1-2, spend a couple of days on each, and switch if you want. You might enjoy something you never expected.
- ✅ **No prerequisites.** You don't need prior cybersecurity or programming experience to attend the inductions.
- 🛠️ **Don't just watch tutorials.** Try stuff, set up tools, break things (legally, obviously 😭).
- 💬 **Ask questions in the group!** Nobody judges basic doubts. We all started at zero.
- 🌍 **Explore beyond this list.** These are just starting points. There's a lot more out there.

## 📝 Optional: write about what you learn

Here's a secret: just "learning" is easy to put off, but writing about it makes it actually stick 😏

If you want to go the extra mile, write a **short report** on something you explored. A Google Doc, Notion page, blog post or GitHub README all work. Include:

- What you tried (a CTF, a tool, a topic)
- What you learned
- Where you got stuck and how you fixed it
- Screenshots or commands, if you have them

**Rules:**

- ✅ 100% optional. Not writing one won't hurt you at all.
- ✍️ Write it in your own words. We can tell when it's copy-pasted 😭
- 📏 Short is fine. 1-2 pages of honest writing beats 10 pages of fluff.
- ⭐ A *genuinely good* report may be considered during the interview, so it can be a real edge.

Share it in the group if you want feedback! 💬
